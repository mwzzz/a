# 店员操作规则

给实际记账的人看，不需要懂技术。

## 多商家（给平台方看）

- 一套系统可以服务多家店，每家店的玩家、班次、押金、流水、设置完全隔离，互相看不到。
- 每个账号只属于一家店；用户名全平台唯一，登录后自动进入自己店，不用选商家。
- 一个人同时只能在一种店里：换店要新建账号。
- 开发者账号登录后进「平台管理」，可以开店、改名、停用商家、给任意店开账号；店老板登录后在「设置 → 账号管理」自己给店员开号。
- 每家店可以同时各有一个进行中的班次，互不影响。
- 停用商家后该店所有账号立即无法登录，数据保留；重新启用即可恢复。

## 开始营业

不需要开班。登录后直接「开一局」，系统按场次记录，所有统计都按日期区间汇总。
对账去「汇总」页，选日期区间即可。

## 开一局

1. 「场次」→「新增场次」（或顶部「开一局」）
2. 只需要选人或上传截图识别，最多 10 个人
3. 茶水默认沿用上次的金额，不再手填；场次名称按「10月31日 第1局」自动生成，时间取当前时间
4. 底部会实时显示「茶水合计」和「有几个人会扣成负数」
5. 点「创建」，每个人的押金自动扣掉茶水，总局数 +1

余额不够也能开局，会扣成负数；但确认前会弹窗提醒，这时最好让对方先补押金。

### 免茶水与黑名单

- 「小工具 → 常用名单 → 免茶水」里的人，开一局时会被自动去掉，不扣茶水、不计局数；分类被改名后这条规则失效。
- 押金低于「茶水 × 11」时，新增场次弹窗会显示提醒，但不会阻止创建。
- 玩家可以标记为黑名单；黑名单玩家不能参加开局，AI 识别和手动选择时也会置灰。

### AI 识别玩家

新增场次时，可以在 AI 区域点击选图、Ctrl+V 粘贴或拖入一张 LoL 房间截图：

- 自动识别双方队伍的真实玩家名，忽略「空」「加入」「邀请/观战」等界面文字
- 相似度 ≥80% 的玩家直接视为匹配并自动填入；72%–80% 会让你从候选里选；没匹配到的可以点「新建并选用」
- 识别完成后，匹配到的玩家会直接填进空位；已有手动选择时先填空位，空位不够会问你是否覆盖
- AI 不会自动创建场次或扣茶水，最终仍要点「创建」
- 识别失败、超时或未启用时会提示原因，仍然可以手动选人

只支持单张 jpg/png/webp/gif，最大 5MB；同一账号每分钟最多识别 10 次。截图只用于本次识别，不会保存。

## 批量新增玩家

「玩家」→「批量导入」，只支持 `.xls` / `.xlsx`：
- 第一列：玩家 id（必填）
- 第二列：押金，单位元（可空，留空就是 0）
- 第一行可以是表头，比如「玩家id / 押金」
- 一次最多 1000 行，文件不超过 5MB

导入前会先整批检查：有重复 id、已存在的玩家、押金为负或超过两位小数，都会列出第几行有问题，并且**整批都不导入**，改好文件再传一次。

「玩家」页右上角还有「导出玩家库」，下载的 Excel 只有游戏名和押金(元)两列，包含本店全部未删除玩家，可直接用 Excel 打开核对或备份。

## 押金操作

在「玩家」页，每一行右边有五个操作：

| 操作 | 规则 |
| --- | --- |
| 加押金 | 必须大于 0，现金押金和总余额增加 |
| 退押金 | 必须大于 0，不能超过当前现金押金，负数账户不能退；有赠金时先不能退，赠金用完后再退 |
| 加赠金 | 管理员和店员都可以操作，赠金只能扣茶水，不能退款或划押 |
| 划押 | 把钱从一个玩家转给另一个，可以划成负数；转出和转入会各记一条流水；有赠金时最多只能划现金押金 |
| 编辑/拉黑/删除 | 删除要求现金押金和赠金都为 0 |

原来的「手动扣押」已经取消，统一并入退押金，避免和真实退款混淆。

划押默认金额是「茶水 × 10」，可以直接改。

### 充值活动与赠金

管理员可以在「设置 → 充值活动」配置多档活动，例如：

- 充 100 元送 20 元
- 充 500 元送 150 元

每次加押金时，系统按满足金额的最高档自动送一次赠金；同一笔只送一次。批量导入玩家不触发活动。

赠金规则：

- 开局扣茶水时先扣赠金，赠金不够再扣现金押金；
- 赠金不能退款、不能划押；
- 玩家还有赠金时不能退现金押金，赠金为 0 后才能按现金规则退款；
- 玩家余额显示为「总余额（押金 现金部分）」，例如 64.00（押金 44.00）；
- 充值活动和赠金都不影响操作人现金差额；赠金抵扣的茶水仍按正常茶水统计。

## 押金颜色

- 红色：低于 30 元，需要提醒对方补押金；总余额为负数一律红色
- 黄色：30 到 60 元
- 绿色：高于 60 元

颜色、押金不足提醒和排序都按总余额（现金 + 赠金）判断。阈值管理员可以在「设置」里改。

## 操作人汇总与对账

钱统一由店长保管，没有开班/交班。系统只负责把每个人该交或该补的金额算清楚。

「汇总」页按日期区间统计每位店员：

| 项目 | 说明 |
| --- | --- |
| 新增场次 | 这段时间他开了几局、多少人次 |
| 茶水 | 他开的局收的茶水合计 |
| 收押金 / 退押金 | 他操作的加押金、退押金金额 |
| 差额 | 收押金 − 退押金 |

**差额就是现金结算依据**：正数是店员应交给店长的钱，负数是店长应补给店员的钱。
划转是玩家之间的账，不涉及现金进出，不计入差额。

场次按「局的时间」归属，押金按「操作时间」归属；补录昨天的局算在昨天。

汇总、流水明细、分红结算的时间筛选都**精确到分钟**，可以只看「今天 20:00 到 22:00」这种时段。默认区间是当天 00:00 到 23:59，快捷项有今天 / 昨天 / 最近三天 / 最近一周。

## 常用名单

「小工具 → 常用名单」用来记店铺规矩：谁是打手、谁免茶水、谁免押金。

- 分类可以自己加、改名、删除（删除会连里面条目一起删，会二次确认）；
- 条目支持增删改和上下移动，编号自动生成；
- 店员和管理员都能改，改完立刻生效；
- 新店默认预置「打手 / 免茶水 / 每天up / 免押金」四类。

## 操作人分红

每个批次会按「建局人」统计：

- 开了几局
- 多少人次
- 扣了多少茶水
- 这个操作人应得的分红

分红有两种方式，管理员在「设置 → 分红方式」里选：

- **按茶水比例**（默认 50%）：分红 = 本人茶水 × 比例，四舍五入到分；
- **每局固定**：分红 = 本人局数 × 每局金额，与茶水多少、人数多少都无关。

关闭的批次会记住交班那一刻的口径（比例或每局金额），之后改设置不影响历史分红。同一个月的不同班次可以用不同口径，结算时会分开计算、合计成一笔。

## 营业日

系统不再按自然日统计，一切以「当前批次」为准。上午 10 点到次日凌晨的班次会完整算在一个批次里，不会被 0 点切开。

## 看记录

「记录」页有两个标签：

- **押金记录**：每一笔钱的变动，谁操作的、什么原因、在哪个场次
- **场次记录**：每一局有几个人、茶水多少、谁开的

顶部搜索框搜玩家；「报表 → 流水明细」里也可以按玩家名或场次名搜索，并选择日期范围。

流水明细支持按操作人筛选。押金记录里选中操作人后，会显示这段时间他的收押金、退押金和差额（收 − 退，正数=店员应交、负数=店长应补），划转不计入。

## 账本

「账本」页是按批次汇总的表，可以导出 CSV 给老板或对账用。批次按开班时间筛选，跨年或跨天会显示完整起止时间。

口径说明：
- 划转只算转出方（一笔划转两边金额相等、方向相反，相加是 0）
- 玩家押金余额是交班那一刻全店押金合计
- 期初 = 期末 − 本批净变动
- 茶水是营业额，交班时上缴管理员，不再留在下一班现金里

「设置 → 数据自检」是技术检查，用来核对玩家现金押金、赠金、流水合计和最后一条余额是否一致。正常营业不用跑；只有手工改过数据库、恢复备份或怀疑数据异常时才需要。交班时系统会自动跑一次，不通过会阻止交班。

## 账号

- 店员：能开局、加/退/划押金、建玩家、改备注；也可以保管现金（需管理员交给他）
- 管理员：额外能删玩家（押金必须为 0）、改设置、开账号、重置密码、跑对账
- 正在保管现金的账号不能直接停用，要先完成交班
- 账号管理只能管本店的人：看到和能操作的都只有自己店的账号。

忘记密码找管理员重置，管理员重置后需要重新登录。

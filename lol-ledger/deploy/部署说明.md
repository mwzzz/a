# 部署说明

目标机器：阿里云 ECS `116.62.242.2`（Alibaba Cloud Linux 4，杭州 `cn-hangzhou-i`，2 vCPU / 2 GB / 40 GB）。
本系统独占 `80` 端口；这台机器是干净的，没有旧站需要让位。

> 历史：2026-11-04 之前部署在轻量服务器 `47.95.146.168`（Alibaba Cloud Linux 3），已整体迁移，旧机不再使用。

## 一、目录规划

```
/opt/lol-ledger/
├── backend/          代码
├── venv/             Python 3.11 虚拟环境
├── frontend/dist/    nginx 静态根目录
├── data/
│   ├── ledger.db     SQLite（+ -wal / -shm）
│   └── backups/      每日备份
├── deploy/
└── .env              JWT_SECRET / DB_PATH / AI_* / LZYUMI_*（root:lol 640）
```

运行用户是新建的 `lol`，不用 root，也不和授权服务混用。

## 二、第一次部署

前提：本机能用密钥 ssh 到服务器（`root@116.62.242.2`，私钥 `%USERPROFILE%\.ssh\_mw.pem`，权限必须是仅本人可读，否则 OpenSSH 拒绝加载）。

```bash
# Windows（PowerShell）
powershell -ExecutionPolicy Bypass -File deploy/push.ps1

# Git Bash / macOS / Linux
bash deploy/push.sh
```

两个脚本等价：构建前端 → 上传代码和 dist → 服务器上没有 venv 时自动执行 `install.sh`。
要临时换机器或换密钥，用 `-Server` / `-Key`（PowerShell）或 `SERVER=` / `SSH_KEY=`（bash）。

`install.sh` 会自动完成：建 `lol` 用户 → 建 venv 装依赖 → 生成 `/opt/lol-ledger/.env`（随机 `JWT_SECRET`）→ 建库 → 装 `lol-ledger-api` 和每日备份 timer → **接管 80 端口**。

接管 80 端口的做法（重要）：

- `/etc/nginx/conf.d/neizhanjizhang.conf` 改名为 `neizhanjizhang.conf.disabled-<时间戳>`，站点文件 `/opt/neizhanjizhang/site` 不删；
- `default.conf` 如果也听 80，同样改名让位；
- 本项目的 server 块写到 `/etc/nginx/conf.d/lol-ledger.conf`，监听 80，`/api` 反代到 `127.0.0.1:8010`。

```bash
# 建开发者账号（只需一次，密码交互输入，不写进任何文件）
cd /opt/lol-ledger/backend
sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db \
  /opt/lol-ledger/venv/bin/python -m app.cli create-superadmin --username admin
```

打开 `http://116.62.242.2/`（安全组已放行 80），用开发者账号登录，会直接进入「平台管理」：

- 右上角「新增商家」：填商家名，可同时建第一个管理员
- 商家行点「账号管理」：建管理员/店员、改角色、启停、重置密码
- 商家行「停用」：该店全部账号立即无法登录，数据保留，可随时启用

首次部署自带一个「默认商家」和一个隐藏的「平台管理」系统商家；后者只挂开发者账号，不出现在商家列表里。

### 开通一家新商家

日常在网页「平台管理」里点：新增商家 → 填商家名和第一个管理员 → 之后在这个商家的「账号管理」里开店员。商家停用后该店全部账号立即无法登录（已签发的令牌也失效），数据保留；改回 `active` 即恢复。

服务器上仍保留一套等价的 CLI，作为网页打不开时的兜底：

```bash
cd /opt/lol-ledger/backend
lg() { sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db /opt/lol-ledger/venv/bin/python "$@"; }

lg -m app.cli create-merchant --name "蜘蛛电竞"
lg -m app.cli create-admin --username zz-boss --merchant "蜘蛛电竞"

lg -m app.cli list-merchants                                  # 看所有商家与账号数
lg -m app.cli list-users                                      # 看账号与所属商家（开发者会标出来）
lg -m app.cli rename-merchant --merchant "蜘蛛电竞" --new-name "蜘蛛电竞（新店）"
lg -m app.cli set-merchant-status --merchant "蜘蛛电竞" --status disabled
```

用户名全平台唯一，建议带商家前缀（`jg-boss`、`zz-01`）。店长也可以自己在「设置 → 账号管理」里建本店店员。

### 恢复原来的官网（仅旧服务器 47.95.146.168 适用）

```bash
sudo mv /etc/nginx/conf.d/neizhanjizhang.conf.disabled-<时间戳> /etc/nginx/conf.d/neizhanjizhang.conf
sudo mv /etc/nginx/conf.d/lol-ledger.conf /etc/nginx/conf.d/lol-ledger.conf.off
```

## 三、日常升级

默认目标已经是新服务器 `root@116.62.242.2` + `%USERPROFILE%\.ssh\_mw.pem`，一条命令即可：

```bash
# Windows
powershell -ExecutionPolicy Bypass -File deploy/push.ps1

# Git Bash / macOS / Linux
bash deploy/push.sh
```

换目标时显式指定：

```powershell
powershell -ExecutionPolicy Bypass -File deploy/push.ps1 -Server root@1.2.3.4 -Key C:\path\key.pem
```
```bash
SERVER=root@1.2.3.4 SSH_KEY=/path/key.pem bash deploy/push.sh
```

脚本会：构建前端 → 传 backend 和 deploy → 传 dist → `pip install` → `python -m app.migrations` → 同步 nginx 配置并 reload → **合并 `.env`** → 重启服务 → 打 `/api/health` → 检查 80 首页。会短暂停服（几秒），建议避开营业高峰。

`.env` 同步规则：默认把本机 `backend/.env` 合并进服务器 `/opt/lol-ledger/.env`，只覆盖本机存在的键，服务器独有键保留；`JWT_SECRET`、`DB_PATH`、`DEBUG`、`CORS_ORIGINS` 永不覆盖；合并前自动备份为 `data/backups/env-<时间>.bak`。不想同步时，PowerShell 加 `-SkipEnv`，bash 用 `SKIP_ENV=1`。

### 数据库版本与回滚红线

当前 schema 是 **v14（多商家 + 开发者账号 + 现金保管 + 分红结算 + 分红方式 + 排队登记 + 取消班次 + 查战绩多用户 + 常用名单 + 玩家黑名单 + 赠金/充值活动 + 撤销加赠金 + 分红按场次认领/冲销）**。升级由服务启动时自动完成：

- v1 库：整库备份到 `/opt/lol-ledger/data/backups/pre-v2-<时间戳>.db`，建商家表并把存量账号/玩家/批次/流水挂到默认商家，旧 `settings` 迁到 `merchant_settings`，同时直接建出最新结构和平台商家。
- v2 库：备份到 `pre-v3-*.db`，加超管列和平台商家；再备份到 `pre-v4-*.db`，加保管人/分红列和交接表。
- v3 库：备份到 `pre-v4-<时间戳>.db`，加 `merchants.custodian_user_id`、`batches.dividend_rate_percent`、`cash_handovers` 表；给每个商家补 50% 分红设置、初始化当前保管人；把所有 `manual_deduct` 流水改成 `refund`，并同步已关班快照的退押金/扣押合计。
- v4 库：备份到 `pre-v5-<时间戳>.db`，加 `dividend_settlements` / `dividend_settlement_batches` 两张表。
- v5 库：备份到 `pre-v6-<时间戳>.db`，给 `batches` 加 `dividend_mode` / `dividend_fixed_cents`（老班次一律 `percent` / 0，金额不变），并给每个门店补 `dividend_mode` / `dividend_fixed_cents` 设置项。
- v6 库：备份到 `pre-v7-<时间戳>.db`，只加「排队登记」表 `queue_entries`。
- v7 库：备份到 `pre-v8-<时间戳>.db`，取消开班/交班：清空班次、现金交接、分红结算历史，场次不再挂班次，押金流水保留但断开批次/场次关联。
- v8 库：备份到 `pre-v9-<时间戳>.db`，**只新增**查战绩五张表 `zj_users` / `zj_batches` / `zj_batch_players` / `zj_queries` / `zj_grants` 与索引，不碰任何既有表。
- v9 库：备份到 `pre-v10-<时间戳>.db`，新增「常用名单」表 `tool_lists` / `tool_items`，并给现有商家预置默认分类。
- v10 库：备份到 `pre-v11-<时间戳>.db`，**只给** `players` 增加 `is_blacklisted` 列，不动历史数据。
- v11 库：备份到 `pre-v12-<时间戳>.db`，给 `players` 增加 `bonus_cents`，重建 `ledger` 表并回填现金/赠金拆分列（保留全部历史行、ID 和 `session_players.ledger_id` 关联），新增 `recharge_campaigns` 表。
- v12 库：备份到 `pre-v13-<时间戳>.db`，`ledger` 的 `reason` 白名单加 `bonus_void` 并新增可空列 `reverses_ledger_id`；重建 `ledger` 表但保留全部历史行、ID 与 `session_players.ledger_id` 关联，非破坏性。v13 相对 v12 是纯增量：旧代码能读写新库，但不认识 `bonus_void`——回滚代码前须先确认库里没有 `bonus_void` 流水（`SELECT COUNT(*) FROM ledger WHERE reason='bonus_void'` 为 0），否则旧代码对账会把它当现金流出而假报警。
- v13 库：备份到 `pre-v14-<时间戳>.db`，新增 `dividend_settlement_sessions`（分红按场次认领，未冲销行里 `session_id` 唯一，DB 级防重复发钱），并给 `dividend_settlements` 加 `voided_at` / `voided_by` / `void_note` 三个可空列以支持冲销；随后把历史结算按「区间内 + 场次创建时间不晚于结算时刻」回填成认领记录，金额一律不回算。**纯加表加列、非破坏性**：回填条数与存量 `session_count` 不一致时只打 WARNING 不阻塞，日志里查 `grep 回填场数`。
  - 上线后必须核对：把「分红结算」页区间拉到月初，确认「已认领 N 场」与回填条数一致；此前被区间去重整段吞掉的活儿会在这里浮现成待结算金额，属于要补发给店员的钱。
  - 回滚：v14 只加表和加列，旧代码不认识新表，**默认只回代码、保留库**。只有在确认回填有问题时才连带还原 `pre-v14-*.db`（代价是丢掉该快照之后的全部场次/押金/结算）；回滚后代码退回「按区间去重」，这期间做过的冲销会被当成已结，必须先人工核对 `SELECT COUNT(*) FROM dividend_settlements WHERE voided_at IS NOT NULL`。

**v8 之前的库不能配新代码跑**：v6 起分红方式、v8 起班次语义都变了，老代码会按旧口径重算或读到已清空的历史。回滚必须「旧代码 + 迁移前备份」成对恢复：

```bash
sudo systemctl stop lol-ledger-api
sudo -u lol cp /opt/lol-ledger/data/backups/<迁移前备份>.db /opt/lol-ledger/data/ledger.db
sudo rm -f /opt/lol-ledger/data/ledger.db-wal /opt/lol-ledger/data/ledger.db-shm
# 把 backend 换回上一版本后再启动
sudo systemctl start lol-ledger-api
```

### AI 识别配置

新增场次的「AI 识别玩家」使用 DeepSeek 视觉模型。Key 只放服务端，编辑 `/opt/lol-ledger/.env`（用 `sudoedit` 或 `nano`，不要 `echo` 到 shell history）：

```bash
AI_ENABLED=true
AI_API_KEY=sk-你的key
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
AI_TIMEOUT_SECONDS=25
```

改完重启：

```bash
sudo systemctl restart lol-ledger-api
curl -s http://127.0.0.1:8010/api/health
```

`AI_ENABLED=false` 或 Key 为空时，前端显示「AI 识别未启用」，手动选人不受影响。截图只在内存转发、不落盘；每用户 10 次/分钟。Key 如果曾经出现在聊天记录或日志里，建议到 DeepSeek 控制台轮换后再更新 `.env`。

### 查战绩（多用户版）

给多个外部用户查「新模式」战队战绩，按次收费：管理员分配次数，用户每点一次「开始查询」扣 1 次。

- 用户入口：`http://116.62.242.2/zj/login`（独立账号，和店长/店员账号完全隔离）。
- 管理入口：用开发者账号登录 → 平台管理 → 「查战绩配额」页签：新增账号、加/减次数、重置密码、启停、看用量流水。
- 计次口径：一次「开始查询」= 扣 1 次，与该批有多少人无关；单批最多 10 人、批次 30 分钟内有效、同一批里每个玩家只能成功查一次（防止「扣 1 次无限查」）。剩余次数为 0 时按钮自动禁用。

上游账号只放服务端 `.env`，用户浏览器拿不到 token、也改不了请求间隔：

```bash
# 推荐：填账号密码，token 过期后端会自动重登
LZYUMI_USER=你的lzID
LZYUMI_PWD=你的密码

# 或者直接贴一个付费 token（不会被自动续期，失效后要手动换）
#LZYUMI_TOKEN=

# 可选调参（不填就是下面的默认值）
#LZYUMI_BASE_URL=https://l.lzyumi.top/lzyumi/lol/info
#ZJ_MIN_INTERVAL_SECONDS=2.5
#ZJ_BATCH_MAX_PLAYERS=10
#ZJ_BATCH_TTL_MINUTES=30
#ZJ_CACHE_TTL_SECONDS=300
```

改完 `sudo systemctl restart lol-ledger-api`。

几个必须知道的约束：

- **必须保持 `--workers 1`**（`lol-ledger-api.service` 里就是 1）。对上游的 2.5 秒全局限速、token 缓存都在进程内，多 worker 会各限各的，容易被上游风控。
- 上游调用是串行的：一批 10 人大概 25~30 秒，前端有进度条和日志。结果按「昵称+大区+场次」缓存 5 分钟，同一批里重复粘贴同一人不会重复打上游。
- 查战绩接口状态码：`503` 表示 `.env` 没配（服务未启用）、`502/504` 表示上游异常或超时、`400` 次数用完或名单不合规、`403` 查了不在本批名单里的人。

排错：

```bash
sudo journalctl -u lol-ledger-api -n 100 | grep -i lzyumi   # 看上游登录/失效日志
sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db \
  /opt/lol-ledger/venv/bin/python -c "
import sqlite3;c=sqlite3.connect('/opt/lol-ledger/data/ledger.db')
print(c.execute('select id,username,quota_total,quota_used,is_active from zj_users').fetchall())
print(c.execute('select count(*) from zj_batches').fetchone())"
```

### 回滚

每次 `push` 之前，部署脚本会把「当前 backend + deploy + frontend/dist」打包成
`/opt/lol-ledger/data/backups/code-<时间>.tar.gz`，保留最近 5 份。所以回滚是一条命令：

```bash
ssh -i ~/.ssh/_mw.pem root@116.62.242.2

# 看有哪些版本
sudo bash /opt/lol-ledger/deploy/rollback.sh --list

# 回到指定版本（会自动停服 → 解包 → 修权限 → 启动 → 打 health）
sudo bash /opt/lol-ledger/deploy/rollback.sh code-20261105-102420
```

**注意**：如果这次发布改过数据库结构（schema 变了），旧代码读不了新库，必须同时还原迁移前的数据库备份（v9 只新增 `zj_*` 表，回滚到 v8 代码时可以保留这些表不还原库；但只要改动涉及既有表，就必须成对恢复）：

```bash
sudo systemctl stop lol-ledger-api
sudo -u lol cp /opt/lol-ledger/data/backups/<pre-vN-时间戳>.db /opt/lol-ledger/data/ledger.db
sudo rm -f /opt/lol-ledger/data/ledger.db-wal /opt/lol-ledger/data/ledger.db-shm
sudo systemctl start lol-ledger-api
```

`rollback.sh` 会在结尾把这段提示再打一遍，并显示当前 schema 版本。

前端 `dist` 已包含在版本包里，一起还原；`index.html` 不缓存，用户 Ctrl+F5 就能拿到旧版。

### 本地开发环境（用生产数据副本）

本地空库测不出真实数据的边界（分页、排序、旧格式）。用生产备份在本地跑一份副本再改代码：

```powershell
# 1) 确认本机有最新备份（每天 04:00 自动拉，也可手动）
powershell -ExecutionPolicy Bypass -File deploy/pull-backup.ps1

# 2) 把最新备份准备成 backend\data\prod-copy.db，并打印商家/玩家/流水统计
powershell -ExecutionPolicy Bypass -File deploy/dev-from-backup.ps1

# 3) 起后端（-Run 直接前台启动，Ctrl+C 停止）
powershell -ExecutionPolicy Bypass -File deploy/dev-from-backup.ps1 -Run

# 4) 另开一个窗口起前端
cd frontend
npm run dev
```

- 副本落在 `backend/data/prod-copy.db`，每次运行都会用最新备份覆盖，**不会碰生产库**；
- 启动时会自动在副本上执行迁移，等于免费做了一次迁移预演；
- 副本里是真实游戏名和金额，只在本机用，别提交到仓库（`backend/data/` 已在 `.gitignore`）。

## 四、备份

- 每天 03:30 自动备份到 `/opt/lol-ledger/data/backups/backup-YYYYMMDD-HHMMSS.db`，保留 30 天。
- 备份用 SQLite 的 backup API，**不能直接 cp**（WAL 模式下会得到不一致副本）。
- 检查定时器与文件：

```bash
systemctl list-timers lol-ledger-backup.timer
ls -lh /opt/lol-ledger/data/backups | tail
```

- **手动跑一次备份**（装完机器、改过部署脚本后都要跑）：

```bash
sudo systemctl start lol-ledger-backup.service
sudo systemctl status lol-ledger-backup.service --no-pager
```

- **恢复演练（强烈建议每次大改后跑）**：验证「备份真的能起服务」，不碰生产库、不占 8010：

```bash
sudo bash /opt/lol-ledger/deploy/verify-backup.sh
```

它会检查文件大小/年龄、`integrity_check`、`foreign_key_check`、schema 版本、与生产库的关键指标对比，再在 8011 端口用备份起一个临时实例打 `/api/health`。

- **异地副本（本机，每天自动）**：

```powershell
# 立即拉一次
powershell -ExecutionPolicy Bypass -File deploy/pull-backup.ps1

# 注册每天 04:00 自动拉取（管理员或当前用户均可）
schtasks /Create /SC DAILY /TN "LOL-Ledger-Backup" /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File \"<仓库路径>\deploy\pull-backup.ps1\"" /ST 04:00 /F
```

默认落在 `%USERPROFILE%\lol-backups`，保留 30 份，拉完会校验 SQLite 文件头。

### 排错：备份服务起不来（status=203/EXEC）

`deploy/*.sh` 必须是可执行权限，否则 systemd 直接拒绝启动：

```bash
ls -l /opt/lol-ledger/deploy/*.sh          # 应该都是 -rwxr-xr-x
sudo chmod 755 /opt/lol-ledger/deploy/*.sh
sudo systemctl start lol-ledger-backup.service
```

`push.ps1` / `push.sh` 已经会在部署后自动修正这个权限（`find ... -name '*.sh' -exec chmod 755`），手工传文件时别忘了。

### 恢复

```bash
sudo systemctl stop lol-ledger-api
sudo -u lol cp /opt/lol-ledger/data/backups/backup-20261031-033000.db /opt/lol-ledger/data/ledger.db
```

## 六、排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面能开，接口全 404 | nginx 的 `proxy_pass` 写了尾斜杠，`/api` 前缀被剥掉。改回 `proxy_pass http://127.0.0.1:8010;` |
| 80 打开还是旧官网 | 还有别的 `conf.d/*.conf` 在听 80（`grep -rn 'listen 80' /etc/nginx/conf.d/`），改名停用后 `systemctl reload nginx` |
| 本机 curl 通、外网打不开 | 只放行了 firewalld 或只放行了安全组。两处都要放行 80（原来的官网就通，通常不用改） |
| `python3` 版本是 3.6 | 必须用 `/usr/bin/python3.11` 建 venv，不能用默认 `python3` |
| 服务起不来 | `journalctl -u lol-ledger-api -n 50`，多半是 `JWT_SECRET` 太短或数据库目录没权限 |
| 登录后立刻被踢 | 令牌里的密码指纹和库里不一致（改过密码），重新登录即可 |
| 登录提示「商家已停用」 | 该账号所属商家被停用了（平台管理或 `set-merchant-status`），改回 `active` 即可 |
| 登录后没有「平台管理」 | 这个账号不是开发者账号。用 `create-superadmin --username <账号>` 升级（或新建一个） |
| 平台管理里商家列表为空 | 该库只有隐藏的平台商家；先「新增商家」，v1/v2 升级上来的老商家会正常显示 |
| 某商家看不到自己数据 | 先确认账号的 `merchant_id`：`list-users` 有商家列；v1 升级后存量账号都在「默认商家」下 |
| 数据自检提示对账不通过 | 有人直接改过数据库里的押金余额。用 `GET /api/v1/reconcile` 看是哪个玩家，改回正确值 |
| 页面白屏 | 看浏览器 Console；多数是 `dist` 没传全，或 `index.html` 缓存。强刷一次 |
| /zj/login 登录提示用户名或密码错误 | 查战绩是独立账号，不是店长/店员账号；先在平台管理「查战绩配额」里新增 |
| 查战绩提示「服务未配置」 | `.env` 里 `LZYUMI_USER`/`LZYUMI_PWD` 或 `LZYUMI_TOKEN` 没填，改完 `systemctl restart lol-ledger-api` |
| 查战绩一直 502 / token 失效 | 上游账号掉线或 token 过期；`journalctl -u lol-ledger-api \| grep -i lzyumi` 看日志，核对 `.env` 密码后重启 |
| 用户点「开始查询」提示次数用完 | 平台管理 → 查战绩配额 → 给该账号「加次数」（负数可扣减，但不能低于已用） |

## 七、换服务器

要搬的东西：`data/ledger.db`（或最新备份）、`backend/`、`frontend/dist/`、`.env`、`deploy/`。
新机器跑一遍 `bash deploy/push.sh`（首次会自动执行 `install.sh` 并接管 80），放行 80，DNS 不用动（本来就用 IP）。

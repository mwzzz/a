# 部署说明

目标机器：阿里云轻量服务器 `47.95.146.168`（Alibaba Cloud Linux 3）。
本系统占用 `80` 端口；原先挂在 `80` 的官网（`/opt/neizhanjizhang/site`）在部署时停用，配置改名保留、随时可恢复，`8000` 的授权服务不动。

## 一、目录规划

```
/opt/lol-ledger/
├── backend/          代码
├── venv/             Python 3.11 虚拟环境
├── frontend/dist/    nginx 静态根目录
├── data/
│   ├── ledger.db     SQLite（+ -wal / -shm）
│   └── backups/      每日备份
├── deploy/
└── .env              JWT_SECRET / DB_PATH（root:lol 640）
```

运行用户是新建的 `lol`，不用 root，也不和授权服务混用。

## 二、第一次部署

前提：本机能用密钥 ssh 到服务器（这台机器是 `root@47.95.146.168`，私钥 `C:/Users/23230/Downloads/test.pem`，已在 `~/.ssh/config` 里配成 `lol-ledger` 别名）。

```bash
# 本机一条命令：构建前端 → 上传代码和 dist → 服务器上没有 venv 时自动执行 install.sh
bash deploy/push.sh
```

`install.sh` 会自动完成：建 `lol` 用户 → 建 venv 装依赖 → 生成 `/opt/lol-ledger/.env`（随机 `JWT_SECRET`）→ 建库 → 装 `lol-ledger-api` 和每日备份 timer → **接管 80 端口**。

接管 80 端口的做法（重要）：

- `/etc/nginx/conf.d/neizhanjizhang.conf` 改名为 `neizhanjizhang.conf.disabled-<时间戳>`，站点文件 `/opt/neizhanjizhang/site` 不删；
- `default.conf` 如果也听 80，同样改名让位；
- 本项目的 server 块写到 `/etc/nginx/conf.d/lol-ledger.conf`，监听 80，`/api` 反代到 `127.0.0.1:8010`。

```bash
# 建商家（首次部署自带一个「默认商家」，可以改名或另开）
cd /opt/lol-ledger/backend
sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db \
  /opt/lol-ledger/venv/bin/python -m app.cli create-merchant --name "极光电竞"

# 建这个商家的管理员（密码交互输入，不写进任何文件）
sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db \
  /opt/lol-ledger/venv/bin/python -m app.cli create-admin --username jg-boss --merchant "极光电竞"
```

打开 `http://47.95.146.168/`（就是原来的 80 端口，安全组本来就放行），用刚建的管理员登录。

### 开通一家新商家

```bash
cd /opt/lol-ledger/backend
lg() { sudo -u lol env DB_PATH=/opt/lol-ledger/data/ledger.db /opt/lol-ledger/venv/bin/python "$@"; }

lg -m app.cli create-merchant --name "蜘蛛电竞"
lg -m app.cli create-admin --username zz-boss --merchant "蜘蛛电竞"

lg -m app.cli list-merchants                                  # 看所有商家与账号数
lg -m app.cli list-users                                      # 看账号与所属商家
lg -m app.cli rename-merchant --merchant "蜘蛛电竞" --new-name "蜘蛛电竞（新店）"
lg -m app.cli set-merchant-status --merchant "蜘蛛电竞" --status disabled
```

商家停用后该店全部账号立即无法登录（已签发的令牌也失效），数据保留；改回 `active` 即恢复。

店员账号不用你开：店长登录后进「设置 → 账号管理」自己建、自己停用。用户名全平台唯一，建议带商家前缀（`jg-boss`、`zz-01`）。

### 恢复原来的官网

```bash
sudo mv /etc/nginx/conf.d/neizhanjizhang.conf.disabled-<时间戳> /etc/nginx/conf.d/neizhanjizhang.conf
sudo mv /etc/nginx/conf.d/lol-ledger.conf /etc/nginx/conf.d/lol-ledger.conf.off
sudo systemctl reload nginx
```

改回来只要把 `lol-ledger.conf.off` 再改回 `lol-ledger.conf`、并把官网配置改名停用即可。

## 三、日常升级

```bash
bash deploy/push.sh
```

如果本机用密钥登录 root（本机已配好 `~/.ssh/config` 里的 `lol-ledger` 别名），这样跑：

```bash
SERVER=root@lol-ledger URL_HOST=47.95.146.168 bash deploy/push.sh
```

脚本会：构建前端 → 传 backend 和 deploy → 传 dist → `pip install` → `python -m app.migrations` → 同步 nginx 配置并 reload → 重启服务 → 打 `/api/health` → 检查 80 首页。

### 数据库版本与回滚红线

当前 schema 是 **v2（多商家）**。v1 库第一次启动时会自动：

1. 把整库备份到 `/opt/lol-ledger/data/backups/pre-v2-<时间戳>.db`；
2. 建 `merchants` 表并把存量账号/玩家/批次/流水挂到默认商家；
3. 旧 `settings` 表迁到 `merchant_settings`，旧表删除。

**v2 库不能配 v1 代码跑**：v1 的查询没有商家过滤，会把所有商家的数据一起返回。回滚必须「旧代码 + 迁移前备份」成对恢复：

```bash
sudo systemctl stop lol-ledger-api
sudo -u lol cp /opt/lol-ledger/data/backups/pre-v2-<时间戳>.db /opt/lol-ledger/data/ledger.db
sudo rm -f /opt/lol-ledger/data/ledger.db-wal /opt/lol-ledger/data/ledger.db-shm
# 把 backend 换回上一版本（v1）后再启动
sudo systemctl start lol-ledger-api
```

### 回滚

```bash
ssh root@47.95.146.168
cd /opt/lol-ledger
sudo systemctl stop lol-ledger-api
# 把 backend 换回上一个版本（git 或你本地留的备份）
sudo systemctl start lol-ledger-api
curl -s http://127.0.0.1:8010/api/health
```

前端回滚同理，把上一份 `dist` 重新传上去即可。`index.html` 不缓存，用户刷新就能拿到。

## 四、备份

- 每天 03:30 自动备份到 `/opt/lol-ledger/data/backups/backup-YYYYMMDD-HHMMSS.db`，保留 30 天。
- 备份用 SQLite 的 backup API，**不能直接 cp**（WAL 模式下会得到不一致副本）。
- 检查：

```bash
systemctl list-timers lol-ledger-backup.timer
ls -lh /opt/lol-ledger/data/backups | tail
sudo -u lol /opt/lol-ledger/venv/bin/python -c "
import sqlite3,glob
f=sorted(glob.glob('/opt/lol-ledger/data/backups/*.db'))[-1]
c=sqlite3.connect(f); print(f, c.execute('PRAGMA integrity_check').fetchone())
"
```

- **每周把最新备份拉到本机**，服务器到期时数据不会一起没：

```bash
scp root@47.95.146.168:/opt/lol-ledger/data/backups/backup-*.db ./lol-backup/
```

### 恢复

```bash
sudo systemctl stop lol-ledger-api
sudo -u lol cp /opt/lol-ledger/data/backups/backup-20261031-033000.db /opt/lol-ledger/data/ledger.db
sudo rm -f /opt/lol-ledger/data/ledger.db-wal /opt/lol-ledger/data/ledger.db-shm
sudo systemctl start lol-ledger-api
```

## 六、排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面能开，接口全 404 | nginx 的 `proxy_pass` 写了尾斜杠，`/api` 前缀被剥掉。改回 `proxy_pass http://127.0.0.1:8010;` |
| 80 打开还是旧官网 | 还有别的 `conf.d/*.conf` 在听 80（`grep -rn 'listen 80' /etc/nginx/conf.d/`），改名停用后 `systemctl reload nginx` |
| 本机 curl 通、外网打不开 | 只放行了 firewalld 或只放行了安全组。两处都要放行 80（原来的官网就通，通常不用改） |
| `python3` 版本是 3.6 | 必须用 `/usr/bin/python3.11` 建 venv，不能用默认 `python3` |
| 服务起不来 | `journalctl -u lol-ledger-api -n 50`，多半是 `JWT_SECRET` 太短或数据库目录没权限 |
| 登录后立刻被踢 | 令牌里的密码指纹和库里不一致（改过密码），重新登录即可 |
| 登录提示「商家已停用」 | 该账号所属商家被 `set-merchant-status` 停用了，改回 `active` 即可 |
| 某商家看不到自己数据 | 先确认账号的 `merchant_id`：`list-users` 有商家列；v1 升级后存量账号都在「默认商家」下 |
| 交班提示对账不通过 | 有人直接改过数据库里的押金余额。用 `GET /api/v1/reconcile` 看是哪个玩家，改回正确值 |
| 页面白屏 | 看浏览器 Console；多数是 `dist` 没传全，或 `index.html` 缓存。强刷一次 |

## 七、换服务器

要搬的东西：`data/ledger.db`（或最新备份）、`backend/`、`frontend/dist/`、`.env`、`deploy/`。
新机器跑一遍 `bash deploy/push.sh`（首次会自动执行 `install.sh` 并接管 80），放行 80，DNS 不用动（本来就用 IP）。

## 账本行为

表：`players`、`sessions`、`ledger`、`settings`。连接使用 `isolation_level=None`，写入用显式事务。旧库会自动加上 `remark`，并去掉「押金和余额不能为负」的检查，因为开局扣茶水允许扣成负数。

玩家库列：序号、游戏 id、押金、总局数、备注。序号是当前排序下的行号，不是库存的 id。排序是总局数从高到低，再按游戏 id 的文本序（所以 `"10"` 会排在 `"2"` 前面）。总押金在玩家页和状态栏。

玩家可以在押金正好为 0 时删除，即使有历史流水。删除会同时删掉该玩家自己的流水。押金不是 0 不能删。

批量导入玩家：一行一个，`游戏id` 或 `游戏id,备注`（英文逗号、中文逗号或制表符）。空行和 `#` 开头跳过。已存在的游戏 id 跳过，不覆盖押金和备注。可从 txt/csv 读入，编码按 utf-8-sig、utf-8、gbk 尝试。

流水原因：`normal_deduct`（只有开一局会写，总局数 +1，茶水可以是 0）、`refund`、`add_deposit`、`transfer_out` / `transfer_in`（同一 `transfer_group_id`）。不能划给自己。退押金和划出不能让余额低于当前押金，所以负数账户不能退、不能划出。

开一局确认时，把当时的茶水写进 `sessions.tea_fee_cents`，并为每个被选中的人写一条 `normal_deduct`。之后再改输入框，不会改已经开过的局。

茶水输入框记在本账本的 `settings.last_tea_cents`。没有这行时显示 2.00 元。离开输入框或关闭窗口时保存。交接导出的是整个数据库，所以这个数会跟着账本走。光标还在框里就马上导出时，文件里可能仍是上一次保存的数。`default_tea_cents` 仍会被初始化成 0，界面已经不用它。

开一局的名单用 `list_session_players`：按该玩家最近一条 `normal_deduct` 的 `session_id` 从新到旧，同一局内按流水 id。没有扣茶水记录的人排在最后。「选前10个」的切换在 `SessionPage._toggle_first`。玩家库、Excel、押金记录下拉框仍用 `list_players`，不要改成开一局的排序。

押金记录：游戏 id 可以下拉，也可以直接输入后点「查询」或回车。从玩家库双击游戏 id 会跳过来并查询当前框里的 id。加押金、退押金、划转必须作用在框里当前这个 id 上。

交接班：导出/导入的是整个 SQLite。导入前会先做 `backup-before-import-*.db`。Excel「导出玩家库」只是当时名单的快照，不能代替账本交接。导入实现是 `shutil.copyfile` 加上 `ensure_writable`，不要改回 `copy2`，否则只读属性会再被带进来。

误开的一局不能撤销。总局数会留下；钱只能再用「加押金」补回去。用户没有要求做反开局。

## 授权

桌面程序不显示服务器地址。空卡密可以提交，是否允许由服务器的试用开关决定。试用开启时，空卡密或未登记的卡密可以登录；已经发放的卡仍然同时只能有一台电脑在线。试用关闭后只接受已发放的卡。改试用不需要重新打包桌面程序，除非还要改登录框的占位文字。

心跳约 20 秒一次。连续两次连不上服务器，主窗口锁定并只能退出。卡被占用、过期、无效则立刻锁定。正常关闭会登出。进程关掉或断网后，服务端约 60 秒没有心跳才会放开这张卡。所以授权服务器停了，已经打开的程序大约几十秒后不能继续用；账本数据仍在本机，服务恢复后重新登录即可。

服务器是阿里云，系统 Python 是 3.6，跑不了这份代码。服务用的是 `/usr/bin/python3.11`，systemd 单元名 `license-server.service`，工作目录 `/opt/neizhanjizhang`，数据库 `/opt/neizhanjizhang/data/cards.db`，监听 `0.0.0.0:8000`。安全组要放行 TCP 8000。SSH 用户是 `admin`，不要用 root 密码登录。本机部署用的私钥在用户 `.ssh` 目录里，名字与 `aliyun_license` 对应；不要把私钥内容写进仓库或文档。

上次会话结束时，服务器上的试用开关是开着的，并且已经有发放出去的卡。卡密不要写入这份文档、不要提交、不要在回复里复述。动手前先在服务器上用 `部署说明.txt` 里的 `--list` 看现状，不要凭记忆去关试用。

授权服务的 SQLite 连接被多个请求共用，偶发竞态还没处理。用户没要求修。

## 用户已经确认过的取舍

- 不要登录账号，也不要「第一个管理员才能写」那种值班锁。交接就是导出整个库、在下一台电脑导入。

## 已知缺口

- 不能撤销已确认的开局。
- 授权服务多线程共用一个 SQLite 连接。
- `run.bat` 把任何启动失败都说成缺依赖。真正的原因要看上面的 traceback。
- 打包程序和源码各有一份 `data\deposit.db`。用户若两处都换过账本，只读或数据问题要分别看。
